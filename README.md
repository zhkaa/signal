# Signal · by Obsidia

MVP пространства для авторов YouTube: подготовка контента, исследование каналов и ниш, публичная статистика и сохранённые проекты.

**Стек:** HTMX, Alpine.js, Node.js/Express, Supabase/PostgreSQL. Шрифт интерфейса — Manrope, надпись Signal — Space Grotesk, иконки — Lucide. Ресурсы загружаются локально.

## Быстрый запуск


```powershell
git clone https://github.com/zhkaa/signal.git
cd signal
npm ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm test
npm start
```

Откройте http://localhost:3000. Для остановки — Ctrl+C. Если репозиторий уже клонирован, обновите чистую рабочую копию через `git pull --ff-only` вместо повторного клонирования.

В `.env` для знакомства оставьте `DEMO_MODE=true`. Сервер слушает только `127.0.0.1`. Команда запуска сама собирает клиент; папку `public` вручную создавать не нужно.

## Возможности и ограничения

| Инструмент  | Что реализовано                                                               |
| ----------- | ----------------------------------------------------------------------------- |
| Оптимизация | Шаблонные названия, описание, теги и чеклист для видео, канала или трансляции |
| Конкуренты  | Поиск каналов и сравнение публичных суммарных показателей                     |
| Ниши        | Сравнение тем по средней просматриваемости выборки до 10 видео на тему        |
| Статистика  | Подписчики, просмотры и количество видео найденного канала                    |
| Проекты     | Сохранение, открытие и удаление результатов оптимизации                       |
| Аккаунты    | Регистрация и вход по email/паролю через Supabase в реальном режиме           |

В деморежиме поиск и статистика показывают **фиксированные учебные примеры** с отметкой в интерфейсе. Проекты изолированы по браузерам и хранятся в памяти сервера: до перезапуска или 24 часов бездействия, максимум 50 на сессию.

Оптимизатор не использует генеративный ИИ. Поиск ниш не является оценкой рыночного спроса. OAuth YouTube, публикация контента, CTR, удержание, доход и история метрик не реализованы.

## Реальные YouTube и Supabase

1. Создайте новый проект Supabase. Выполните файлы `supabase/migrations/01_profiles.sql` … `05_constraints.sql` один раз в указанном порядке в SQL Editor.
2. Настройте Email в Supabase Authentication, Site URL и подтверждение почты. Пользователь подтверждает email и затем входит в приложении.
3. В Google Cloud включите YouTube Data API v3 и получите серверный API key. Поисковые запросы расходуют квоту; исследование ниш выполняет несколько запросов.
4. Заполните `.env`: `SUPABASE_URL`, `SUPABASE_ANON_KEY` (anon JWT проекта), `YOUTUBE_API_KEY`, `DEMO_MODE=false`.
5. Перезапустите сервер и выполните [проверку БД](docs/database-checks.md).

Service-role ключ не нужен. Сервер проверяет JWT пользователя, а PostgreSQL RLS ограничивает доступ к его проектам. JWT хранится в памяти страницы: после перезагрузки или истечения срока нужно войти заново. Автообновление токена и его серверный отзыв при выходе не реализованы.

Реальная интеграция с YouTube/Supabase требует ключей и отдельной проверки; локальные тесты не подтверждают работу внешних сервисов или применение SQL-миграций. `.env` исключён из Git. Для публичного развёртывания потребуется отдельная настройка HTTPS, прокси, доступности сервера и ограничения квот.

## Команды

| Команда                | Назначение                                                            |
| ---------------------- | --------------------------------------------------------------------- |
| `npm start`            | Сборка клиента и запуск сервера                                       |
| `npm run dev`          | Наблюдение за исходниками; страницу после изменений обновлять вручную |
| `npm run build`        | Сборка HTML-компонентов, CSS, JS, шрифтов и иконок                    |
| `npm test`             | Сборка и 7 проверок API/ресурсов/демоизоляции                         |
| `npm run format`       | Форматирование исходников                                             |
| `npm run format:check` | Проверка форматирования                                               |

## Структура и команда

- `src/client/` — HTML-компоненты, стили и клиентские действия.
- `src/server/` — маршруты, middleware и сервисы.
- `supabase/migrations/` — схемы, ограничения и RLS.
- `tests/` — тесты **в корне**, рядом с `src`.
